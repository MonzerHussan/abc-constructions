# ABC — Feedback Collection System (نظام جمع الملاحظات)

**المرحلة:** Pilot Preparation Phase  
**الغرض:** النظام الموحد لجمع ملاحظات العينة عبر جميع القنوات أثناء Pilot  
**المكمل لـ:** `FEEDBACK-FRAMEWORK.md` (قواعد تقييم الملاحظات)  
**نظام البيانات:** كل سجل يستخدم `entity_id` من **Unified Stakeholder Model** (`PILOT-DATA-ARCHITECTURE.md`) — ليس معرف استبيان مؤقتاً  
**التعدد اللغوي:** يُجمع التغذية الراجعة باللغات الثلاث (عربي/إنجليزي/أوردو) ويُوحَّد في عمود `feedback` واحد (انظر `MULTI-LANGUAGE-STANDARD.md`)

---

## 1. قنوات جمع الملاحظات

| القناة | البيانات المُجمعة | الأداة | التردد |
|--------|-------------------|--------|--------|
| **استبيان كمّي** (Typeform) | إجابات مغلقة + نص مفتوح (C-V1/S-V1) | Typeform → Sheets | مرة واحدة (أسبوع 3-4) |
| **مقابلات معمقة** | قصص ألم/قيمة، سلوك ماضٍ، WTP | `INTERVIEW-SCRIPT.md` + تسجيل | 30-45 دقيقة |
| **First Transaction** | طلبات حقيقية، Quotes، مطابقات | سجل FT مخصص | مستمر (أسبوع 3-6) |
| **ملاحظات ميدانية** | انطباعات، حواجز، أسئلة | دفتر الملاحظات | أثناء كل تفاعل |
| **Follow-up (WhatsApp/Email)** | تأكيد نية الدفع، تعليقات | قالب رسالة | بعد الاستبيان |

---

## 2. سجل التوثيق الموحد (Unified Log)

| الحقل | التفصيل |
|-------|---------|
| `entity_id` | معرف الكيان الموحد (ENTITY-XXXXX) — ثابت عبر كل الأدوات |
| `entity_category` | CUST / SUPP / ECO / INT |
| `segment` | Contractor / Supplier / Partner / ... |
| `date` | التاريخ |
| `channel` | Survey / Interview / FT / Field / Referral |
| `question_ref` | C-XX / S-XX / FT / ملاحظة |
| **`language`** | **اللغة الأصلية للرد (ar/en/ur)** |
| `raw_feedback` | النص الأصلي (أي لغة) |
| `feedback_summary` | تلخيص موحد (عربي/إنجليزي) للتحليل |
| `type` | سلوك سابق / نية / دفع / ألم |
| `weight` | 🔴 حرج / 🟠 مهم / 🟡 تكميلي |
| `assumption_ref` | معرف الافتراض من `PILOT-ASSUMPTION-TRACKER.md` |
| `schema_field` | الحقل الهدف في المخطط الموحد (§5 من البنية) |
| `lead_score` | من Lead Scoring Framework (§6 من البنية) |
| `status` | جديد / موثّق / مُقفَل |

> **قاعدة:** كل ملاحظة تُربط بافتراض واحد على الأقل + تُحدَّد قيمتها في المخطط الموحد — لا تُسجَّل ملاحظات بلا إسناد.
> **قاعدة اللغات:** النص الأصلي يُحفظ في `raw_feedback` (أي لغة) وتُرصد `language`، والتحليل يعتمد `feedback_summary` — فلا تضيع أي معلومة لغوية.

---

## 3. آلية تحويل الملاحظات إلى أدلة

1. **التجميع:** تُصدَّر إجابات Typeform إلى Google Sheets يومياً مع `entity_id`.
2. **الترميز:** يُرمّز النص المفتوح (ألم، قيمة، سعر، حواجز) برموز موحدة.
3. **الربط:** كل دليل يُربط بالافتراض ومعيار النجاح + الحقل الهدف في المخطط الموحد.
4. **التقييم:** تُحدَّث نقاط Lead Score لكل Entity (Strategic/Engagement/Commercial/Conversion).
5. **التحديث:** تُحدَّث `PILOT-SUCCESS-SCORECARD.md` و`VALIDATION-DASHBOARD.md` أسبوعياً.
6. **المراجعة:** جلسة أسبوعية لمطابقة الأدلة مع قواعد القرار (Proceed/Modify/Pivot).

---

## 4. فلاتر جودة الملاحظات

| الفلتر | القاعدة |
|--------|---------|
| صحة الإجابة | يُستبعد أي رد يكتمل في < 60 ثانية |
| تكرار | يُستبعد الردود المكررة (نفس البريد/IP) |
| ملاءمة الشريحة | يُستبعد غير SMB (إن لم يلبي C-02/S-03) مع حفظه كملاحظة |
| إسناد | أي دليل بلا `assumption_ref` يُعاد ترميزه أو يُستبعد |
