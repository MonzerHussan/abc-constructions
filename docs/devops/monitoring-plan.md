# خطة المراقبة والتنبيه — منصة ABC (Beta)

**التاريخ:** 2026-08-01

---

## 1. الأهداف

- رصد صحة النظام وتوافره وأدائه وأمانه أثناء Beta.
- تنبيه مبكر قبل تأثر المستخدمين.
- أساس بيانات لقرارات ما بعد Beta.

## 2. المستويات

| المستوى | الأداة المقترحة | النطاق |
|---|---|---|
| Uptime & API | UptimeRobot / Better Uptime | الصفحة الرئيسية، `/api/auth/check-credentials` |
| أخطاء التطبيق | Sentry (مقترح) | أخطاء runtime على الخادم والعميل |
| أداء الواجهة (Web Vitals) | Vercel Analytics / Lighthouse CI | LCP, CLS, INP, TTFB |
| قاعدة البيانات | أدوات الاستضافة (Neon/Supabase dashboards) | اتصالات، زمن استعلام، CPU |
| السجلات (Logs) | منصة الاستضافة / Loki | سجلات الخادم وauth |
| الأسرار/الاعتماديات | Dependabot + npm audit في CI | تحديثات وثغرات |

## 3. مؤشرات التنبيه (مقترح)

| المؤشر | الحد | الإجراء |
|---|---|---|
| Uptime | انقطاع > 60 ثانية | تنبيه فوري |
| أخطاء 5xx | > 1% في 5 دقائق | تنبيه فوري |
| أخطاء 4xx على /api/seed | أي طلب ناجح | تحقيق أمني |
| محاولات دخول فاشلة مرتفعة | > 20/دقيقة من IP واحد | مراجعة rate limiter/WAF |
| زمن استعلام DB | > 500ms متوسطاً | فحص الفهارس/الاستعلامات |
| استخدام القرص للملفات المرفوعة | > 70% | تنظيف أو نقل لـ S3 |

## 4. قياسات أداء Beta (خط الأساس)

- تسجيل TTFB وLCP للصفحات الحرجة قبل الإطلاق ثم أسبوعياً.
- تسجيل عدد المستخدمين النشطين وطلب/ثانية لمعرفة حدود النمو.

## 5. تشغيل المراقبة محلياً (اختياري)

```bash
npm run build
npm start
# افتح /_next/… أو استخدم curl لقياس TTFB
curl -w "TTFB: %{time_starttransfer}s\n" -o /dev/null -s http://localhost:3000/
```

## 6. خارطة ما بعد Beta

- تثبيت Sentry + Vercel Analytics فور النشر.
- إعداد تنبيهات Telegram/Slack عبر المتصدرين أعلاه.
- مراجعة شهرية: أخطاء، أداء، ثغرات، استهلاك موارد.
