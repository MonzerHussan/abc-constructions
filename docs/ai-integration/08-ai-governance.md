## 1. الغرض والنطاق

وثيقة حوكمة تحكم كل قدرة AI في المنصة: من استهلاك البيانات، مروراً باستخدام النماذج، ووصولاً للمخرجات المعروضة للمستخدم. **إلزامية لكل Sprint تنفيذي (AI-0b فما بعد).**

- ✅ يسري على: نطاق `modules/ai/`، البوابة، المستهلكين، المكونات UI، المزوّدين الخارجيين.
- ✅ يسري على: كل القدرات (Matching, Search, BOQ, Tender, Pricing, Extraction).
- ⛔ لا يغيّر أي ADR معتمد — يلتف حول القيود القائمة ولا يكسرها.

---

## 2. المبادئ الحاكمة

| المبدأ | المعنى العملي |
|--------|---------------|
| **Human-in-the-Loop** | كل قرار تجاري نهائي يتخذه إنسان؛ AI يقدّم توصية لا قراراً نهائياً |
| **الشفافية (G1/G4)** | كل ناتج AI يظهر بمستوى ثقة + إمكانية فهم الأسباب (`reasons`) |
| **لا وصول مباشر** | AI يقرأ عبر Public Read Interfaces (G1) ويستهلك أحداثاً (G2) فقط |
| **التحكم المركزي** | كل استدعاء نموذج يمر عبر `AiGateway` (لا استدعاءات متفرقة من الخدمات) |
| **التوقف الآمن** | Feature Flags لكل قدرة + Kill Switch مركزي |
| **الأقل تكلفة الكافي** | لا LLM حيث تفي القواعد (G3): القواعد أولاً، ثم النموذج |

## 3. الأدوار والمسؤوليات

| الدور | المسؤولية |
|-------|-----------|
| **AI Council (مقترح)** | اعتماد قدرات AI الجديدة، سياسات البيانات، استثناءات الحوكمة |
| **Product Experience** | اعتماد مكوّنات AI وقرارات عرض المخرجات (G4) |
| **Architecture Review Board** | اعتماد البنية والعقود قبل التنفيذ |
| **Data Owner (كل Domain)** | يوافق على واجهات القراءة العامة الخاصة به (G1) |
| **Security & Compliance** | مراجعة الوصول والخصوصية والتشغيل |
| **Programmer (AI)** | التنفيذ وفق هذه الوثيقة دون تعديلها دون اعتماد |

## 4. حوكمة البيانات

| البند | القاعدة |
|-------|---------|
| **الوصول** | عبر Public Read Interfaces فقط — لا مباشر لـ DB (G1) |
| **نوع البيانات** | يُسمح: بيانات المنتجات/الموردين/العروض المجهلة حسب الحاجة (G1/G3) |
| **PII** | لا إرسال بيانات شخصية حساسة للنماذج الخارجية إلا بموافقة + تعمية |
| **الاحتفاظ** | سجل الاستخدام وفق سياسة الاحتفاظ المتفق عليها (راجع 03-ai-usage-tracking-model) |
| **المتجهات (Vectors)** | تُخزَّن محلياً في PostgreSQL + pgvector (لا خارج المنصة) |
| **الملفات** | تُقرأ من Storage module عبر مرجع `fileId` — لا تحميل كامل غير منضبط |
| **مصادر المخرجات** | كل مخرجات قائمة على مستندات تُظهر `sourceLinks` (Grounded Outputs) |

---

## 5. حوكمة النماذج والمزوّدين

| البند | القاعدة |
|-------|---------|
| **التسجيل** | كل مزوّد/نموذج يُسجَّل في `AiModel` (الاسم، القدرة، التكلفة) قبل الاستخدام |
| **التفعيل** | النموذج النشط فقط (`isActive`) يُستخدم عبر البوابة |
| **الإصدار** | تثبيت إصدار النموذج في السجل — لا "أحدث إصدار" تلقائياً |
| **التحقق** | PoC لكل قدرة قبل الإطلاق (جودة + تكلفة + امتثال) |
| **نماذج إقليمية** | للمستندات الحساسة: نماذج محلية/إقليمية (Roadmap 5.3) |
| **الاستبدال** | أي استبدال مزوّد يمر عبر البوابة دون تغيير عقود الخدمات |

## 6. حوكمة المخرجات

| البند | القاعدة |
|-------|---------|
| **مستوى الثقة** | كل ناتج AI يعرض `AiConfidenceBadge` (G4) |
| **الأسباب** | كل توصية تعرض أسباباً (`reasons`) — لا "الصندوق الأسود" |
| **الهلاوس** | النموذج لا يخترع حقائق: أي رقم/مصدر غير مؤكد يُوسم `unverified` |
| **الـ Fallback** | عند فشل/انخفاض الثقة → نتيجة قواعدية محددة سلفاً مع إشعار `fallback` |
| **المراجعة البشرية** | النتائج النهائية القابلة للتأثير التجاري تمر بمراجعة بشرية قبل اعتمادها |
| **التغذية الراجعة** | `AiFeedback` يغذي تقييم الجودة دورياً |

**مستويات القرار:**

| المستوى | المثال | التدخل البشري |
|---------|--------|---------------|
| L1 — معلوماتي | اقتراح بحث، تطبيع بند BOQ | بدون موافقة (يُعرض للتصحيح) |
| L2 — مساعد | تطابق موردين، تقدير تكلفة | مراجعة قبل الاعتماد |
| L3 — قرار تجاري | سعر عرض، شراء | قرار بشري حتمي (Human-in-the-Loop) |

## 7. الجودة والتحيز

| البند | القاعدة |
|-------|---------|
| **قياس الجودة** | Precision@K، Fallback Rate، رضا المستخدم (AiFeedback) |
| **تحيز المورّدين** | نتائج المطابقة تُراجع لعدالة الفئات/المناطق — لا إقصاء ضمني |
| **اللغة** | الجودة مقاسة في اللغات الثلاث (ar/en/ur) — العربية أساسية |
| **التحديث** | مراجعة جودة دورية بعد Pilot وقبل توسيع النطاق |

---

## 8. التدقيق والسجلات (ADR-009)

- كل استدعاء يُسجَّل في `AiUsage` (مزوّد، نموذج، حالة، رموز، تكلفة، زمن) — **لا استثناء**.
- `requestId` يربط الطلب بالنتيجة للتحقيق.
- سجل القرارات البشرية (من اعتمد ماذا ومتى) ضمن وحدة التدقيق القائمة.

## 9. الامتثال والخصوصية

| البند | القاعدة |
|-------|---------|
| **سيادة البيانات** | بيانات المستندات الحساسة لا تغادر النطاق إلا عند الضرورة وبموافقة |
| **مقدمي الخدمة** | عقد مع المزوّدين يوضح عدم استخدام البيانات للتدريب |
| **الشفافية للمستخدم** | إفصاح واضح عند كل ناتج AI ("نتيجة ذكية — راجعها") |
| **سجلات الموافقات** | أي استثناء يُوثَّق ويُعتمد من AI Council |

## 10. إدارة الحوادث

| الحادثة | الاستجابة |
|---------|-----------|
| Prompt Injection / خرق | تعطيل القدرة عبر Feature Flag + مراجعة أمنية + سجل |
| تسريب بيانات | تعطيل المزوّد + إشعار امتثال + مراجعة السجلات |
| انهيار مزوّد | تبديل تلقائي عبر البوابة إلى المزوّد البديل (Fallback) |
| تدهور الجودة | خفض عتبة الثقة + تحويل للنمط القواعدي |
| تكلفة شاذة | إنذار + خفض الحصص + Kill Switch (راجع 09) |
