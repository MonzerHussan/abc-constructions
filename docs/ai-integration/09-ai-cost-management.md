## 1. الغرض

إدارة تكلفة استدعاءات النماذج **كأولوية هندسية** منذ التصميم: تقليل الاستدعاءات المكلفة، توجيه القدرات للنموذج الأنسب، وربط التكلفة بالإيرادات (نموذج Credits). **هذه الوثيقة تكمل نموذج التتبع (03) ولا تكرره:** 03 يسلّم "كيف نُسجِّل ونحسب"، وهنا "كيف نُقلِّل ونضبط ونُخطط".

---

## 2. مبدأ التكلفة الحاكم

> **G3 في الممارسة:** لا ندفع مقابل ما تستطيع القواعد فعله.
> ترتيب التنفيذ الصارم لكل قدرة: **قواعد/Retrieval → نموذج صغير/رخيص → LLM كامل → Vision/OCR** — ولا ينتقل للدرجة التالية إلا عند الحاجة المقاسة.

| الطبقة | مثال | التكلفة النسبية |
|--------|------|-----------------|
| قواعد + Retrieval (pgvector) | بحث نصي/متجهي، مطابقة فئات | ~0 |
| نموذج صغير (نماذج embedded/رخيصة) | تطبيع وحدات، تصنيف | منخفضة |
| LLM متوسط | تطبيع بنود BOQ، توليد أسباب | متوسطة |
| Vision/OCR | مستندات ممسوحة ضوئياً | مرتفعة |

## 3. روافع خفض التكلفة (Cost Levers)

### 3.1 تخزين مؤقت (Cache) — أعلى رافعة
- **Cache بـ `AiUsage.cached`**: الطلبات المتكررة (نفس الإدخال/الهاش) لا تستدعي المزوّد.
- تطبيقات: تطبيع بنود BOQ المتكررة، أسئلة بحث شائعة، توصيات عامة.
- سياسة TTL حسب الحساسية (سعر: قصير؛ فئات/وحدات: طويل).

### 3.2 تقليل الرموز (Token Reduction)
- **مدخلات قصيرة وموجّهة**: تمرير الحقول اللازمة فقط (لا المستند كاملاً).
- **قسمة (Chunking)**: المستندات تُقسم قبل الإرسال (راجع Sprint AI-1: Pipeline).
- **مخرجات مضبوطة**: `max_tokens` + JSON-schema إلزامي لمنع التوهان.
- **نموذج أسرع للترتيب الأولي** ثم LLM فقط لإعادة الترتيب (Re-rank) للمرشحين المختصرين.

### 3.3 اختيار النموذج الأمثل (Model Tiering)
| السيناريو | النموذج المقترح |
|-----------|-----------------|
| تصنيف/تطبيع بسيط | نموذج صغير/رخيص |
| استخراج من نص PDF نظيف (Text Layer) | LLM متوسط (بدون Vision) |
| مستند ممسوح | Vision أولاً ثم LLM للنصوص المستخرجة |
| توليد أسباب عالية الجودة | LLM قوي (عند الضرورة فقط) |

### 3.4 معالجة غير متزامنة وتجميع (Batching)
- BOQ/مستندات: معالجة عبر `AiJob` (خلفية) — لا استدعاءات متزامنة كثيرة.
- تجميع عدة بنود في استدعاء واحد (نموذج متعدد البنود) بدل استدعاء لكل بند.

### 3.5 Embeddings متقنة
- يُخزَّن المتجه ويُعاد استخدامه (لا إعادة حساب لنفس النص).
- تحديثات تدريجية فقط عند تغيّر البيانات.

### 3.6 نماذج محلية (Roadmap 5.3)
- للاستخراج/OCR المتكرر الحساس: نموذج محلي/إقليمي يقلص التكلفة ويعزز الامتثال.

## 4. الميزانية والتخصيص (Budgeting & Allocation)

| البند | القاعدة |
|-------|---------|
| **ميزانية شهرية** لكل قدرة ومنظمة (من `AiQuota`) |
| **حصة إجمالية للمنصة** (Backstop) — تجاوزها يُفعّل إنذار + إبطاء |
| **عتبات إنذار**: 50% / 80% / 100% من الميزانية |
| **تعطيل تلقائي** عند العتبة القصوى (غير القدرات المضمونة SLA) |

### 4.1 واجهة المراقبة
- لوحة "تكلفة AI" (أدمن): يومياً/شهرياً حسب قدرة/مزوّد/نموذج/منظمة.
- مؤشرات: **Cost per Inference · Cost per Feature · Cost per Active User · Cache Hit Rate · Fallback Rate**.

### 4.2 الربط بالإيرادات (Business Model)
| العرض | ما يشمله | التكلفة المقابلة |
|-------|----------|------------------|
| Free | حدود منخفضة (Retrieval-أول) | قريبة من الصفر — يُدار بـ Quota |
| Starter | حصص مطابقة + BOQ أساسية | محدودة بميزانية الباقة |
| Premium | غير محدود + رؤى | Credits تمتص التكلفة |

> **القاعدة:** **لا يُشغَّل LLM مكلف في باقة لا تمتص تكلفته** — النموذج Tiering حسب الباقة.

---

## 5. التنبؤ والتقدير (Forecasting)

- **قبل كل قدرة جديدة (PoC):** تقدير تكلفة/مستخدم/شهر = (استدعاءات × رموز وسطية × سعر) — بوابة قرار قبل الإطلاق.
- **بعد الإطلاق:** مقارنة التقدير بالواقع من `AiUsage` شهرياً؛ أي انحراف > 20% يُستعرض في Sprint Review.
- **معدل النمو:** النموذج يكون أرخص حسب السيناريو المتوقع (عدد المستخدمين × المعدل).

## 6. الحماية والطوارئ

| الآلية | الوصف |
|--------|-------|
| **Quota Pre-check** | رفض قبل الاستدعاء (مبكراً) — `AI_QUOTA_EXCEEDED` |
| **Rate Limit** | حد استدعاءات/دقيقة لكل منظمة/ميزة |
| **Budget Kill Switch** | تعطيل قدرة معينة عند بلوغ سقفها |
| **Fallback للتكلفة** | عند الضغط: LLM → نموذج رخيص → قواعدي (مع إشعار `fallback`) |
| **Monitoring** | إنذار عند شذوذ التكلفة (جرت العادة: سبايك بسبب خلل/هجوم) |

## 8. مؤشرات النجاح (KPIs)

| المؤشر | الهدف |
|--------|-------|
| Cache Hit Rate | ≥ 40% (قابلة للقياس بعد Pilot) |
| Fallback Rate | < 10% |
| Cost per BOQ extract | أقل من حد معتمد (يُثبَّت بعد Pilot Data) |
| نسبة LLM/Retrieval | ≤ 25% من الاستدعاءات الكلية |
| انحراف الميزانية | ≤ 20% شهرياً |
