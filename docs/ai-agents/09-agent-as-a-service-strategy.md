هذه الوثيقة **تحفظ فكرة مسار منتج** — تأجير **Platform Business Agents** للشركات كموظفين رقميين. تُدرس وتُفعل فقط **عند المرحلة المناسبة** بعد نضج **ABC Agent Operating System** (Sprint AI-2) وثبات بنيته. أي قرار تنفيذي هنا يتطلب: اعتماد Architecture + اعتماد Business + مراجعة Governance (08) قبل الفتح.

## 1. Product Vision (الرؤية)

### 1.1 مفهوم AI Workforce

التحول من "أدوات ذكاء اصطناعي تخدم منصة ABC" إلى **قوة عمل رقمية قابلة للتأجير**: شركة تستأجر وكلاء AI متخصصين (خدمة عملاء، مبيعات، تسويق، مالية، قانون، HR، تحليلات، أمن، إدارة) **كموظفين رقميين** حسب الحاجة — دون توظيف بشري.

### 1.2 الفرق بين AI Feature و AI Employee

| البعد | AI Feature | AI Employee |
|-------|-----------|-------------|
| الدور | وظيفة داخل تطبيق موجود | كيان عامل مستقل بخلفية ودور |
| المسؤولية | نتيجة/اقتراح | ملكية مهمة + تفاعل مستمر |
| السياق | سياق الجلسة | ذاكرة طويلة + معرفة الشركة |
| الحساب | يُفعل ضمن حساب | "موظف" برخصة/مقعد |
| الإشراف | إعدادات بسيطة | إشراف بشري + حوكمة عمل (Human-in-the-Loop) |

### 1.3 حالات الاستخدام للشركات

| القطاع | مثال |
|--------|------|
| تجارة إلكترونية | CS Agent يرد على العملاء 24/7 + Sales Agent يؤهل الزوار |
| شركة عقارية | Marketing Agent يدير حملات + Analytics Agent يقيس |
| شركة استشارية | Legal Agent يراجع عقود + HR Agent يفرز مرشحين |
| مصنع/مقاول | Finance Agent يرصد فواتير + Procurement/Admin Agent |

> القيمة = تقليل التكاليف التشغيلية (Staff-as-a-Service) مع إبقاء **القرار البشري** حاكماً (08).

## 2. Business Model (نموذج الأعمال)

| النموذج | الوصف | متى يناسب |
|---------|-------|-----------|
| **Subscription (باقة)** | اشتراك شهري/سنوي لعدد وكلاء محدد | تبني سهل، إيراد متوقع |
| **Per Agent** | سعر لكل وكيل نشط | وضوح للمستخدم |
| **Per Seat** | سعر لكل "مقعد عمل" (مستخدم بشري يُشرف على الوكيل) | الشركات المتوسطة |
| **Usage Credits** | دفع حسب الاستدعاءات/الاستخدام (ربط 09) | استخدام متغير |
| **Enterprise License** | ترخيص مخصص لحجم/وكلاء/عزل كامل | الشركات الكبرى/الحكومية |

**المبدأ الحاكم:** مزيج **Subscription أساسي** (تغطية) + **Usage Credits** (فائض) — مع **Enterprise License** للعزل الكامل (SLA/دعم مخصص).

> لا أرقام الآن — تُثبَّت بعد Pilot (نفس نهج 09-pricing-strategy و Sprint AI-2 §8).

## 3. Multi-Tenant Concept (العزل متعدد الشركات)

### 3.1 كيف تستأجر شركة Agent خاصاً بها

```
شركة → تسجيل → اختيار باقة/وكلاء → تهيئة (معرفة + أدوات + سياسات)
     → تفعيل "موظف رقمي" → إشراف بشري → فواتير (اشتراك + Credits)
```

| العنصر | القاعدة |
|--------|---------|
| كل شركة = **Tenant** مستقل | معرفة وذاكرة وصياغة وهوية خاصة |
| الوكيل باسم الشركة | هوية `agent.{ecosystem}.{role}` داخل نطاق الشركة |
| الإشراف | مدير الشركة يعيّن `approvalRole` لكل وكيل |

### 3.2 عزل بيانات كل شركة

| البند | القاعدة |
|-------|---------|
| **Tenant Isolation** | لا يرى وكيل شركة (أ) بيانات شركة (ب) — لا بيانات ولا ذاكرة ولا متجهات |
| الفهارس (RAG) | كل شركة فهرس خاص `orgId` (توسعة تسليم 6 AI-2) |
| الذاكرة | `AiMemory` بنطاق `org` معزول (تسليم 4 AI-2) |
| الحصص | `AiQuota` لكل شركة (09) |

### 3.3 ملكية الذاكرة والمعرفة

- **المعرفة (Knowledge Base)** ملك للشركة: تُرفع/تحدَّث/تُحذف بواسطتها — كاملة السيادة.
- **الذاكرة** ملك الشركة: الحق في النسخ/التصدير/المسح (08 §9 "الحق في النسيان").
- لا يُستخدم تدريب/معرفة شركة لتحسين وكلاء شركة أخرى (08 §4).

### 3.4 صلاحيات الوصول

- مدير الشركة يتحكم في: من يُشرِف، ما الأدوات المكشوفة، من يوافق على إجراءات عالية التأثير (تسليم 5 AI-2).
- التكامل مع RBAC الخاص بالشركة المستأجرة عند الاقتضاء.

## 5. Customization Model (التخصيص)

| بُعد التخصيص | الطريقة |
|--------------|---------|
| **قطاع الشركة** | قوالب قطاعية (تجارة/عقار/استشارات/إنشاءات) + إعادة تكوين قدرات الوكيل |
| **سياساتها** | قواعد عمل/موافقات الشركة تُحمّل كـ (Procedural memory + Tool ACL) |
| **Knowledge Base** | رفع مستنداتها (سياسات/كتالوج/أسئلة شائعة) → فهرس RAG خاص (تسليم 6) |
| **أدواتها المتصلة** | ربط أدوات خارجية (ERP/CRM/تذاكر) عبر **Integration Gateway** فقط — لا اتصال مباشر |

| القاعدة | التفصيل |
|---------|---------|
| تخصيص بالتهيئة لا بالكود | كل الاختلاف عبر بيانات/سياسات — لا فروع كود لكل عميل |
| إصدار المعرفة | نسخة من KB للشركة (قابل للتراجع) |
| لا تمييز بالقطاع | القوالب أساس، التخصيص يُراجع (08 §7 جودة) |

## 6. Security & Governance (الأمن والحوكمة)

### 6.1 Tenant Isolation
- عزل منطقي صارم (بيانات/ذاكرة/فهارس/حصص) — لا تسرب بين الشركات.
- عزل تطبيقي إضافي اختياري (Enterprise) حسب العقد.

### 6.2 Data Ownership
- البيانات/المعرفة/الذاكرة **ملك الشركة المستأجرة** — حقوق نسخ/تصدير/حذف.
- لا استخدام بيانات الشركة خارج عقدها (08 §4/§9).

### 6.3 Consent Management
- موافقة صريحة على: جمع الذاكرة، مشاركة البيانات الخارجية (نماذج)، استخدام السجلات.
- موافقة قابلة للسحب في أي وقت (توقف فوري للوكيل).

### 6.4 Audit Logs
- كل تفويض/أداة/قرار مسجل بهوية وكيل + `requestId` (ADR-009) — وتقارير دورية للشركة.
- سجل الإشراف البشري (من اعتمد ماذا).

### 6.5 Human Approval Rules
- الإجراءات عالية التأثير (مالية/قانونية/شراء) → موافقة `approvalRole` إلزامية (تسليم 5 AI-2 + 08 §6).
- انتهاء مهلة = رفض افتراضي.
- وكيل لا يملك صلاحية كتابة خارج أذوناته.
